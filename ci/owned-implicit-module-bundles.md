# 0059: retain owned implicit compiler module bundles

Clang writes implicit header-module PCMs into the producer worker's private module cache and records their absolute paths in the main BMI. Removing that worker directory invalidates the published main BMI. This patch retains the original producer module-cache directory as part of the immutable owned generation; it does not relocate those dependency paths or remove compiler flags.

The main file remains `payload.pcm`. Durable records distinguish main bytes from total retained output bytes. Copies reserve/copy only main bytes and persist the existing stable-companion identity; independent worker acquisition holds both the copy and complete stable generation. The original capture/output reservations remain separate: publication requires total retained output to fit the output envelope. Captured source snapshots, startup protocol data and lease/FIFO files are removed after natural worker reap and before publication. The retained unit has an explicit bundle marker; orphan unit collection cannot erase it.

Inventory is bounded: one completed producer unit, 128 known module-cache regular files, directory-depth checks, 4608 inventory entries and paths shorter than 1024 bytes. Unknown files, links, changed identities, failed inventory, changed publication snapshots or quota failures reject publication/lookup/collection and preserve the durable charge. Traversal and deletion use directory FDs with no-follow identity checks. The digest records complete bounded inventory metadata; it is not an asserted byte-content security digest. Compiler source/AST validation remains required for lookup. A full inventory is fsynced and checked again before converting the existing reservation into its actual charge. Collection first marks retirement durably and retains the charge through partial cleanup/retry.

The existing `.owned-payload-v1` namespace uses layout version 2 (new magic/record size), rather than opening another independently bounded namespace. Existing version-1 ledgers fail closed and are not silently migrated or erased. Owned worker request protocol 4 makes old version-3 workers reject the new contract before frontend/output work. Unowned legacy protocols remain supported. This Linux owned-payload mechanism bounds logical retained compiler payload in one shared namespace, not physical allocation, process RSS or all machines' unrelated caches.

## Qt follow-up remains open

`json-control-matched.json` retains the original Qt CDB/flags and explicit matching clang resource directory. Nlohmann's producer now naturally builds and publishes a retained bundle; subsequent validation accepts that main BMI. All four JSON qualified requests still return empty. The real `std.cc` scan reports `_Builtin_inttypes`/`intmax_t` errors and main reports missing `std`, but a diagnostic-only unsaved draft commenting out that import still returns empty (`json-without-std-diagnostic.json`). That control exposes `module_file_conflict`: textual Qt headers first load `_Builtin_stddef` from the consumer implicit cache, then the named JSON BMI references a distinct producer-owned `_Builtin_stddef` PCM. A minimal real clang++ importer compiles `nlohmann::json` and `value.empty()` successfully, and actual compiler code completion returns `json`/`json_pointer` (`json-import-compiler-control.json`, `json-compiler-completion.json`). Thus retained bundle lifetime is working; coordination of consumer/producer implicit module identities remains necessary. Missing std alone does not explain the JSON failure. These controls are not a complete context/insertion or latency qualification and no performance gate is claimed.

The initial `json-control.json` accidentally omitted the explicit resource directory and failed with missing `stddef.h`; it remains retained as an invalid resource-identity control, not patch evidence. Original disk source/CDB and compiler `-fmodules` were not altered.
